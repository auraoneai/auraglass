**Scope in one line.** PLAT owns the whole `release/4.x` line (4.1.1 trust patch, 4.2/4.3/4.4 bridge releases, 4.x LTS), the 5.0 build, exports, packaging and artifact gates, the GitLab pipeline and npm publishing, the change-class and deprecation machinery, the compat composition, the `migrate 4to5` engine and the CLI, the registry build, the docs site and agent DX, and the removal of `legacy/**`.

**What PLAT does not own** (each is a contract seam, never a wait): token, material, motion, preference and a11y content (MAT); component code, metas, prop tables, compat adapters and codemod mapping data of other streams (CMP, SURF, MAT, each in its own `src/compat/<stream>/` and `fragments/codemods/<stream>.ts`); certification lanes, Storybook, Material Lab, showcases and the GA checklist runner (QUAL); the org-managed `mirror-to-gitlab` workflow (OD-8, outside every PRD).

**Deviations from the archived PRDs (declared).**

1. *GitLab replaces GitHub Actions everywhere.* Archived `publish-npm.yml`, `glass-pipeline.yml`, `change-class.yml`, `artifact.yml`, `canaries.yml`, `cli.yml`, `registry.yml`, `docs.yml`, `removal-gate.yml` and every `actions/*` step become jobs in `ci/plat.gitlab-ci.yml` (contract §4.13). `GITHUB_WORKFLOW_REF` becomes the GitLab OIDC identity; `gh run` becomes `glab ci status` or `scripts/ci/gitlab-status.mjs`; artifacts use `expire_in`; Pages replaces `gh-pages` and Vercel previews; the trusted publisher moves to GitLab (OD-10).
2. *No CI job reads GitHub.* Change class reads commit markers, `.changeset/*.md` bump types and committed decision records, never PR labels. The archived `visual-bug-fix` label, `perf-budget-raise` label and `multi-family` label become committed records or commit trailers (REQ-PLAT-20, -21, -76). Operator-only steps (branch protection, GitHub Releases, Discussions, fragment-sync PRs, consumer grep) use the machine's existing `gh` login from a PLAT worktree and are never CI.
3. *`release/4.x` exists from C0* (cut at `v4.1.0`), not from `v4.2.0`. 4.1.1 lands on `release/4.x`; `main` is frozen until GA; 5.0 lands on `next`.
4. *Removal is deletion of `legacy/**`.* With the C0 quarantine (contract §3.1a), FND's 13 removal families delete quarantined files that are already outside the 5.0 build. The archived "removal waits for the successor" ordering disappears; the consumer grep, advisory and revertability gates remain (REQ-PLAT-79..83).
5. *Per-stream fragments replace shared files.* Deprecations, codemod mappings, size budgets, CSS assembly, side-effect exceptions and lane registrations are read through `loadFragments(kind)` (S-50). Archived single files (`deprecations.json` hand-edited, `docs/size-budgets.json` edited by MODIFY, `mappings/*.json` generated by `gen-deprecations.mjs`) are generated aggregates.
6. *Deprecation ids* use the per-stream space `DEP-P0001`, `DEP-M…`, `DEP-C…`, `DEP-S…`, `DEP-Q…` (S-38) instead of `DEP-\d{4}`.
7. *Blocks moved by the contract.* PLAT authors only the `auth` and `settings` blocks and the items `code-surface`, `diff-viewer`, `gantt`, `kanban`, `react-hook-form`, `rich-text`, `transfer-list` (contract §3.3). `support-inbox`, `mobile-settings`, `schema-viewer` and `ai-sdk-adapter` are SURF's.
8. *Frozen toolchain.* Root dependencies are frozen at C0 (§4.12). Archived tool choices outside that set (`ajv`, `pngjs`, `acorn`, `es-module-lexer`, `lightningcss`, `size-limit`, `tsc-alias`) are replaced by frozen tools: TypeScript compiler API for AST scans and schema checks, esbuild for CSS lowering and byte budgets, tsdown for declarations' alias rewriting. Workspace dependencies of `packages/{cli,registry,mcp}` are added by one PLAT contract PR (CP-PLAT-1, §22).
9. *PRD path.* The orchestrator writes this file to `docs/auraglass-5/prd/`; contract row A18 lists `docs/auraglass-5/<file>`. Closed by contract PR CP-PLAT-2 (§22); content is unaffected.

## 1. Problem

AuraGlass 4.1.0 is published and used, but the platform around the components is not trustworthy, and 5.0 is the largest break the library will ever ship.

- **Unsafe 4.x.** Root import starts behaviour tracking (`src/utils/adaptiveAI.ts:84,150-190`), `GlassCanvas` evaluates strings with `new Function` (`src/components/cms/GlassCanvas.tsx:315`), conditional hooks crash `GlassInput` (109 lines in 24 files), `aura-glass/primitives` and `/theme` crash in Server Components, 84 reduced-motion sites leave content at `opacity: 0`, ContrastGuard fabricates WCAG results, and the hosted backend bakes a public default `JWT_SECRET` with no advisory.
- **Dishonest claims.** README, `llms.txt` and `RELEASE_NOTES_4.1.0.md` claim "498 visual targets certified" while the verifier prints `0/498`; "optional backend" while 15 backend packages are hard `dependencies`; "SSR-safe" while the root is one client boundary.
- **Unreproducible releases.** 4.1.0 was published from a laptop with 4 uncommitted edits; `prepublishOnly` fails on npm ≥11; Pipeline Validation has been red since v3.3.0; a token publish path exists; 73 versions in 11 months, 8 breaking commits shipped as patches, and a CHANGELOG/tag/npm ledger that contradicts itself.
- **A broken artifact.** `{ GlassButton }` costs 559,909 B gzip; the tarball is 9.65 MB packed / 49 MB unpacked; 23 runtime dependencies; types and runtime disagree on six subpaths; 6 `.d.ts` files carry `@/` aliases; 200 `!important` in shipped CSS; two build systems.
- **No migration path.** No API report, no `deprecations.json`, zero runtime deprecation warnings, no codemods, a CLI inside the runtime package with no `init`, `diff` or dirty-tree refusal, 28 recipe strings that break layout, and docs where 79 of 278 snippets fail `tsc`.
- **A repository that cannot be worked in.** 47,342 of 50,127 tracked files (2,930 MB) are committed evidence in `reports/`; 45 probe scripts sit in the root; 152 REMOVE records hold 39% of attributed lines.
- **Sequential planning.** The archived 19-PRD plan had 1,487 cross-group dependency edges and 75 shared files, and its CI was five GitHub workflows. The user requires GitLab CI only and concurrent streams.

This PRD makes the platform honest, reproducible, cheap to consume and mechanically migratable, and does it in a stream that never waits for another.

## 3. Desired end state

**4.x line (`release/4.x`).**

1. `aura-glass@4.1.1` is the first release published from a GitLab tag pipeline (`plat:publish:npm`) by npm trusted publishing over GitLab OIDC, with a provenance attestation naming project `chahal-foundation-group/github-auraoneai/auraglass`, `.gitlab-ci.yml` and the tag commit. No token path exists anywhere. The tag pipeline's PLAT gate jobs are all `allow_failure: false` and green.
2. 4.1.1 contains exactly the §13.1 cuts plus the accepted crash/privacy intake (command-palette regex, cookie consent, React 19 unit matrix), with no `dependencies`, `peerDependencies` or `exports` change; every observable removal carries a `fragments/deprecations/plat.ts` entry with an `exception`.
3. `reports/` and the 45 probe scripts are gone from the tree on every branch (no history rewrite); evidence is GitLab job artifacts with `expire_in`.
4. The hosted-runtime advisory is published before the 4.1.1 tag; the font decision is recorded; claims are retracted and a claims lint keeps them out.
5. 4.2.0 ships the dependency diet (optional peers, install-level C-D), real per-entry builds, a deprecation entry and dev warning for every known 5.0 removal, the deferred 4.x fixes and `doctor --v5`; 4.3.0 ships the `preview="v5"` wiring, `compat/*.css`, C-D on every rename, and `@auraglass/cli` 0.x with `migrate 4to5 --dry-run`. 4.x LTS runs 12 months after GA under `v4-lts`.

**5.0 line (`next`, then `main` at GA).**

6. One build (`npm run build` = `npm run tokens:build && tsdown`, then `postbuild`) emits a preserved-module ESM graph with per-file `"use client"`, `.d.ts` without aliases, layered CSS assembled from `fragments/css/*`, and `exports` generated from `build/exports.manifest.json`. `aura-glass` is `"type": "module"`, Node `>=20.19`, React `^19.0.0`, no `bin`.
7. Importing any file of `dist/` has zero side effects; `sideEffects` is `["**/*.css"]`; dependencies are exactly `@base-ui/react@1.8.0`, `clsx@2.1.1`, `@tanstack/react-table@8.21.3`, `@tanstack/react-virtual@3.14.13`; the tarball is ≤2,000,000 B packed with no maps, fonts, tests, contracts, fragments or seeds.
8. Every PR on `next` and `release/4.x` has a computed change class; a removal reaches GA only if its deprecation shipped in a published 4.x minor (G-07); deprecations are one per-stream fragment set that generates warnings, `deprecations.json`, the migration guide, compat coverage and the release notes.
9. `npx @auraglass/cli migrate 4to5` runs 8 core and 6 area transforms with fixtures; on the frozen 4.x consumer fixture it leaves zero TODOs on the flagship subset and the result builds.
10. `@auraglass/cli`, `@auraglass/registry` and `@auraglass/mcp` publish from the same tag pipeline; the registry is shadcn CLI v4 compatible; the docs site, Storybook and the Material Lab are served from GitLab Pages; README, docs, release notes and `llms.txt` render numbers only from run artifacts.

| **C-I (visual fix)** | as C-I but a default-mode cell changed, and a committed record `docs/release/visual-fixes/<slug>.json` in the same PR lists exactly those cells, the D-28 or §13.1 id and the composite artifact URL | `release/4.x` patch and minor |
| **C-E** | only additions: exports, optional props, widened inputs, subpaths, optional peers, `data-ag-*` attributes, CSS variables | 4.x minor; `next`; 5.x minor |
| **C-D** | adds deprecation entries + `@deprecated` TSDoc + dev warning (runtime kinds) + codemod id or `automation: 'manual'`; no behaviour or pixel change | 4.x minor; 5.x minor |
| **C-D (install-level)** | a dependency moves to an optional peer on a 4.x minor **and**: a `kind: 'dependency'` entry with `since` = this version exists; every importer loads it lazily or behind its own subpath and a missing install throws `Error("[aura-glass] <pkg> is now an optional peer; install it: npm i <pkg>")`; `doctor --v5` reports undeclared consumer imports; the release notes list it first | 4.x minor only |
| **C-B** | removed/renamed export, subpath or prop; narrowed input or widened output; new required prop; changed default; raised peer/engine floor; removed `require`; removed CSS variable or global selector; public DOM/ARIA/`data-*`/part change; removed dependency; visual change without a record | `next` pre-releases (G-07 decides what reaches GA); 6.0 for `compat` |

4.x patches allow C-I and C-I (visual fix) plus `exception` entries; 4.3 is the last minor that may add a 5.0 deprecation (4.4 only for late finds); 5.x patches allow C-I, 5.x minors C-I/C-E/C-D. A commit `!` or `BREAKING CHANGE:` with a computed class below C-B fails; a computed C-B without `!` fails; any `!` on `release/4.x` fails. The `.changeset/<stream>-*.md` bump type must be ≥ the computed class (patch ≥ C-I, minor ≥ C-E/C-D, major = C-B).

2. *Visual re-baselining (B11)*: 4.3 `preview="v5"` per subtree a full minor ahead.

5. *Deep imports* (`aura-glass/dist/...`, documented at `INSTALLATION.md:176`) stop resolving; `imports-subpaths` rewrites known ones; `transpilePackages` is no longer needed.
6. *Duplicate contexts disappear* (single `*.context.ts`): apps that relied on two theme contexts converge on the provider value (release-note line under B10).
7. *Type-level refs*: `ComponentPropsWithRef<typeof Button>` changes shape; flagged by API report diffs.
8. *Hydration fixes in 4.1.1* show the fallback for one commit and assume reduced motion until effects run, matching the server.
9. *Font change in 4.1.1*: system UI replaces Aeonik; licensed apps redefine `--glass-font-sans`; consumer baselines need re-approval.
10. *Codemod damage*: dirty-tree refusal makes `git checkout .` a full restore; each transform bug is fixed fixture-first.
11. *Doctor no longer fails on Radix/MUI*, because 5.0 targets drop-in use in shadcn apps.
12. *Low consumer visibility* (~156 downloads/week, no telemetry): the 12-month LTS window is only ever extended.
13. *Rollback*: REQ-PLAT-33 runbook; because 4.1.0 contains the privacy and security defects, a forward 4.1.2 is preferred over rolling back 4.1.1.
14. *GitLab latency (W-6)*: pushes to `next`, `release/4.x` and stream branches reach GitLab at the next `main` push or the daily reconcile; the merging stream may ask the owner to dispatch the mirror; OD-8 removes it.

1. 4.1.1: under `prefers-reduced-motion: reduce` every affected component settles visible (`opacity` 1, identity transform) in jsdom and in the remote Chromium run (no visible text node with computed `opacity < 1` 500 ms after load; `document.getAnimations().length === 0` for the subtree 1 s after mount); zero `data-meets-wcag` in any 4.x story DOM; `GlassInput`'s `aria-describedby`/`aria-invalid`/label ids unchanged by the hooks hoist; video controls keep labels with a `data:` source; the font change does not regress the remote contrast sample (17/342 failures, +0); `jest-axe` suites in touched folders stay green.
2. No migration path lowers an accessibility floor: compat adapters and codemods never emit props or CSS that re-enable glass or motion under `forced-colors`, `prefers-contrast: more`, `prefers-reduced-transparency` or `prefers-reduced-motion` (B13); 4.x props that forced animation or transparency (`forceVisible`, motion overrides) are dropped with a warning.
3. Codemods preserve `aria-*`, `role`, `id`, `htmlFor`, `tabIndex`, `data-testid` byte-for-byte (`preserve-a11y-attrs` cases); compat adapters map 4.x accessible-name props (`label`, `aria-label`, `title`, `ariaLabel`) to the 5.0 accessible name — PLAT's generic adapter test asserts role and accessible name parity on the frozen fixture with `@axe-core/playwright` (colour contrast on).
4. Selector tables list ARIA moves per component (from `MigrationRow.selectors`); the guide recommends role/name queries.
5. Deprecation warnings go to the console only; nothing is rendered or announced.
6. D-28 fixes ship with composites that include the measured contrast ratio per text run (REQ-PLAT-59).
7. CSS distribution keeps `ag.a11y` last in every order statement so forced-colors, contrast and reduced-transparency rules win without `!important`; every bundle with component rules carries their `ag.a11y` rules (REQ-PLAT-74); `AuraGlassScript` stays importable from a Server Component layout (canary).
8. Canaries, blocks and docs routes: 0 serious/critical axe violations (colour contrast on; Chromium and WebKit; blocks also under forced colors, `prefers-contrast: more` and reduced motion), landmarks, one `h1`, full keyboard reachability, touch targets ≥24×24 (≥44×44 primary mobile), OCR contrast ≥4.5:1 body / ≥3:1 large and glyphs (REQ-PLAT-97, -102).
9. CLI output never relies on colour alone; release notes and guides pass heading-order, link-text and alt-text lint.

Formerly shared files are PLAT-owned generators over per-owner fragments (`loadFragments`, S-50) or discovered inputs (metas, `registry-item.json`, canary pages, fixture cases).
- **Residual non-dependency waits** (contract §7.3): W-5 external decisions, W-6 mirror latency, W-7 npm trusted-publisher re-pointing (only the publish step waits; dry-runs proceed).
