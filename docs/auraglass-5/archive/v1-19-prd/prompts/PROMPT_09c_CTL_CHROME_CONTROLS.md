## 4. Steps
1. **Button (CTL-055..060).** Build the full REQ-CTL-21 API (SC-24 grammar), following the PRD §4.1 sketch: `variant` regular|clear|identity (material axis, default `regular`), `prominent`, `intent` neutral|danger (status tint, default `neutral`), no `material` prop, `refraction`, `loading`, `startIcon`/`endIcon`, `pressed`/`defaultPressed`/`onPressedChange` (root is Base UI `Toggle` when any is present; adding/removing them logs one dev warning), `disabled`, `focusableWhenDisabled`, `render`, `type="button"`, `ref`. `materialProps({ layer:'chrome', interactive:true, variant, prominent, refraction })`; `data-ag-intent` is set when `intent !== 'neutral'` (replaces `data-ag-button-variant`, SC-21); `cn` from `src/utils/cn.ts`. Parts `root`, `icon` (`aria-hidden`), `label`, `spinner` (only while loading), `hit-area` (A11Y-065). Loading: `aria-busy="true"`, click not fired, label kept with `visibility:hidden` so width doesn't change, spinner static under `motion=calm|none`, accessible name kept. More than one `data-ag-prominent` per view root (nearest chrome-bar surface, else the document; `data-ag-view` is not a registered attribute) logs one dev warning (checked once on mount with `closest()`; no observer). `intent="danger"` tints rim/specular only and uses `--ag-sys-color-danger` text; it never changes the material. No magnetic code in core (REQ-CTL-26).
2. **IconButton (CTL-061..065).** Shares Button internals (same chunk, ≤1 KB delta). `aria-label` is TS-required (`tests/types/icon-button.test-d.ts` proves omission is an error) and an empty string logs a dev error. `shape` capsule (default) | fixed. Square 28/36/44, ≥24 at compact. Glyph colour `var(--ag-on-surface)`, which follows `data-ag-backdrop` without JS.
3. **Toolbar / ButtonGroup / ToggleGroup (CTL-066..073).** `Toolbar.Root` is a `SurfaceGroup` (`data-ag-group`, chrome, regular, capsule when horizontal) with the only backdrop; items carry `data-ag-surface`, `shape="concentric"` and **no `::before` blur**. Base UI Toolbar supplies roving focus (`loop` default true), Home/End, disabled skip unless `focusableWhenDisabled`, and caret keys for `Toolbar.Input`. `ButtonGroup` (in `ButtonGroup.tsx`, no hooks, no directive) is `role="group"` with required `aria-label | aria-labelledby`, `orientation`, `attached` (default true), no roving focus. `ToggleGroup` on Base UI `ToggleGroup` + `Toggle` with `value: string[]`, `multiple` (default false; deselecting the last item is allowed). Item radius = `max(0, root radius − inset)` through `--ag-radius-inner` (±0.5px).
4. **CTL-074 Toolbar overflow (P2).** Items opt in with a `priority="low"` prop; the emitted `data-ag-priority` attribute awaits MAT ratification in SC-21 (PRD §21 O-06) — report it, don't invent another attribute. Only if PRD-OVL's Menu (OVL-081) is merged (`rg --files src/components | rg '/Menu\.meta\.ts$'` returns a file); otherwise leave `todo` and say so (5.1-eligible per PRD §19). Never build an ad-hoc menu.
5. **SearchField (CTL-075..080).** `Field` + Base UI `Input type="search"` + an AuraGlass `IconButton` clear (`aria-label` = `clearLabel` ?? messages "Clear search"). `control-shell` uses `materialProps({ layer:'chrome', thickness:'thin', shape:'capsule' })`; it is the only glass input, and inside a `SurfaceGroup` it has no `::before` blur. Props per REQ-CTL-101 (`onClear`, `clearLabel`, `shortcut` renders a `Kbd` hint and registers **no** global listener, `loading` → spinner in `adornment-end` + `aria-busy`, `variant` (material axis), `refraction`). Escape (element `onKeyDown`, never a document listener) clears a non-empty value, calls `onClear` and stops propagation; on empty it propagates to A11Y's `LayerStack` (A11Y-049, the only Escape dispatcher, SC-25). The clear button renders (and is tabbable) only when the value is non-empty. Hide `::-webkit-search-cancel-button` (`appearance: none`) so there is exactly one clear affordance. Zero `!important` (replaces `LiquidGlassSearchField.tsx:52-53,70-71`).
6. **SegmentedControl (CTL-081..086).** Base UI `RadioGroup` + `Radio` (REQ-CTL-40, decided by SC-38 / erratum E-08: `ToggleGroup` emits `aria-pressed`, not `role="radio"`; switch only if the CTL-001 check proves radio semantics). `Root` (`value`, `defaultValue`, `onValueChange`, `size`, `variant` (material axis, SC-24), `refraction`, `orientation`, required `aria-label`, `name`), `Item`, `Indicator` (auto-rendered). Track = `SurfaceGroup` (chrome, regular, capsule). Indicator = `transient`, thin, concentric: inner fill at rest; while moving it gets glass + `data-ag-animating` (adds `will-change: transform`), removed on `transitionend`. Movement by `transform` + `width`, measured with exactly one `ResizeObserver` on the root; View Transition (`view-transition-name: ag-seg-<useId()>`) when supported and motion is full, else CSS transition with `spring.snappy` `linear()` ≤`--ag-duration-small`; jump under `calm|none`. No deselection. Overflow: no wrap; `@container` switches labels to ellipsis with ≥44px items and `title` = full label. More than 5 items at ≤390px logs one dev warning recommending `Select`. Record the pinned RadioGroup Home/End behaviour in `SegmentedControl.meta.ts` `keys.homeEnd` from an observed test.
