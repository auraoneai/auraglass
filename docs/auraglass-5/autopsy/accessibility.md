# AuraGlass 5.0 Autopsy: Accessibility

Scope: `src/components/accessibility`, contrast utilities (`src/utils/contrastGuard.ts`, `src/utils/contrast.ts`, `src/hooks/useAutoTextContrast.ts`, `src/hooks/useLiquidGlassBackdrop.ts`), focus primitives (`src/primitives/FocusScope.tsx`, `src/primitives/focus/*`, `src/primitives/RovingFocusGroup.tsx`), global CSS media handling (`src/styles/glass.css`), 12 complex widgets checked against the WAI-ARIA APG, the a11y reports in `reports/`, the tests, and GitHub issue #16. I read the code and ran no browser. The Read tool returned nothing for the certification PNGs, so this report makes no visual claims from screenshots.

## Summary and score: 3 / 10

AuraGlass has a lot of accessibility surface area: about 12.4k lines in the files listed above, 5 focus-trap implementations, 4 reduced-motion hooks or providers, 3 settings providers, 359 test files that call `jest-axe`, and a 1,124-line "GlassA11y" control panel. Very little of it does what its name says.

- **Contrast adaptation is not real.** The "ContrastGuard" parses the default text colour `var(--glass-text-primary)` as white (`src/utils/contrastGuard.ts:182,545-546`). Its improvement math is invented (`:470, :481, :509-510`). When something throws, it reports a pass (`:685`). The CSS variables and class it writes have no consumers. In `LiquidGlassMaterial`, its "fix" sets CSS `opacity` on the whole surface, so the text it is meant to protect gets fainter (`src/primitives/LiquidGlassMaterial.tsx:330-332`).
- **System preferences are only partly honoured.** Every `prefers-contrast` query uses the obsolete `high` keyword, which current browsers do not match (16 occurrences, 0 use `more`). `prefers-reduced-transparency` and `forced-colors` are only handled for a few legacy class names. The canonical inline material (`createGlassStyle` / `buildSurfaceStyles`, 126 calls in 59 component files) and the flagship `LiquidGlassMaterial` hard-code literal `backdrop-filter` values, so those CSS overrides never reach them.
- **Keyboard support in complex widgets is inconsistent and often wrong.** `GlassSlider` has no keyboard handler at all. The date picker grid has no grid semantics or arrow keys. The tooltip only opens on mouse hover. The accordion is built with tab roles. Menus, menubar, tree, tabs and the date picker put every item in the Tab order instead of using roving tabindex. `RovingFocusGroup` exists, but no component uses it.
- **The tests cannot catch any of this.** `jest-axe` runs in jsdom, where the color-contrast rule cannot evaluate. Most axe tests render a component with default props. The contrast spec only checks white text over a fixed dark backdrop, and there is no browser-level axe test. The November 2025 reports claim things the code does not do ("100% focus coverage", "ContrastGuard integrated into 76 components"). The 3.2/3.3 certification ledgers are honest that manual screen-reader and touch passes are still pending, which is issue #16.

For the "premium first-party design system" bar, the core problem is this: a translucent material over arbitrary content needs a real legibility contract (scrim, vibrancy, or opaque fallback), and AuraGlass's contract is a 2–10% white gradient plus hope (`src/tokens/glass.ts:995-1000`).

## What is excellent (keep)

- **Honest certification ledgers.** `reports/3.2-release/accessibility-certification.md:3` and `reports/3.3-release/accessibility-certification.md:3` say plainly that they are not manual screen-reader certification, and they mark most widgets "Partial". Issue #16 (open since 2026-05-14) forbids claiming SR/touch certification. Keep this discipline.
- **The DOM-grid backdrop sampler is a real foundation.** `sampleLiquidGlassBackdrop` (`src/hooks/useLiquidGlassBackdrop.ts:117-170`) samples the DOM behind an element on a grid, classifies `light / dark / mixed`, and computes `requiresDimming` for the `clear` variant. `LiquidGlassMaterial` uses it to add a dark scrim (`src/primitives/LiquidGlassMaterial.tsx:390-396`). This is the right shape for 5.0, though it is limited to colour-based backgrounds.
- **The CSS fallback blocks are correct in intent.** `src/styles/glass.css:4022-4110` provides reduced-transparency (opaque bg, no blur), forced-colors (`Canvas`/`CanvasText`, no shadows, no blur) and `@supports not (backdrop-filter)` fallbacks with `!important`, which do override inline styles on the classes they target.
- **`GlassDropdownMenu` is the best menu.** It has a portal, `DismissableLayer`, `aria-haspopup/expanded/controls`, menuitemcheckbox/radio with `aria-checked="mixed"`, Arrow/Home/End, Escape that returns focus to the trigger, and submenu Right/Left (`src/components/navigation/GlassDropdownMenu.tsx:229-231,352-367,510-511,791-797`).
- **`GlassCombobox` follows the right pattern.** Focus stays on the input, with `role=combobox`, `aria-activedescendant`, option ids, `aria-autocomplete=list`, grouped `role=group`, and `onMouseDown preventDefault` to keep focus (`src/components/input/GlassCombobox.tsx:99-188`). It is a good template.
- **Tabs keyboard logic.** It handles orientation-aware arrows, Home/End, and automatic vs manual activation (`src/components/navigation/GlassTabs.tsx:325-361`).
- **Touch token.** `--glass-touch-target-min: 44px` (`src/styles/tokens.css:363`) is the right number.

## What is mediocre

- **Focus styling is fragmented.** There are at least four systems:
  - `.glass-focus` is defined twice with different mechanics: outline at `src/styles/glass.css:549-552`, then `outline:none` plus a box-shadow ring at `:4236-4250`.
  - Global element selectors (`button:focus-visible, a:focus-visible, [tabindex]…`) in `src/components/accessibility/GlassFocusIndicators.css:78-91` are pulled into the shipped `dist/styles/index.css`. They overwrite `box-shadow` on every focused element in the consumer's whole app.
  - `GlassFocusRing.module.css` and `FocusIndicator.tsx`.
  - 126 inert Tailwind `outline-none` / `focus:ring-*` class strings in TSX, for example `focus-visible:ring-white/10` at `src/components/navigation/GlassContextMenu.tsx:442`. A 10% white ring would fail 1.4.11 even if Tailwind were present.
- **The focus colour is one fixed hue.** `--glass-focus-ring-color: hsl(var(--glass-color-primary))` (`src/styles/design-tokens.css:46`) is a single colour over arbitrary backdrops. No two-tone ring (inner light + outer dark) guarantees 3:1 against unknown content.
- **Touch targets.** `GlassButton` sizes `xs` = 24px and `sm` = 32px (`src/components/button/GlassButton.tsx:595-596`). There is no `pointer: coarse` media query anywhere in `src`, so there is no coarse-pointer enlargement. The `glass-touch-target` class is sprayed onto `glass-sr-only` elements and then neutralized (`src/styles/glass.css:2925-2933`), which is evidence of a mechanical codemod rather than design.
- **Dialog/Modal.**
  - `GlassDialog` puts `role="dialog"` on the full-screen backdrop wrapper (`src/components/modal/GlassDialog.tsx:582-586`).
  - Escape is a global `document` listener, so stacked dialogs all close at once (`:238-249`).
  - The background is not made `inert`.
  - `GlassModal` runs both `FocusTrap` and its own initial-focus and restore-focus logic (`src/components/modal/GlassModal.tsx:340-375,841-845`).
  - Both components emit analytics-style attributes onto the dialog DOM (`data-user-stress`, `data-interaction-count`, `data-time-spent`, at `GlassDialog.tsx:591-594` and `GlassModal.tsx:795-797,838`).
- **`GlassDataGrid` is semantically a table, not a grid.** It uses `role="table"` with sortable `columnheader` + `aria-sort`, focusable headers, and Enter/Space sort (`src/components/data-display/GlassDataGrid.tsx:207,287-345`). That is acceptable, but there is no APG grid cell navigation despite the name. The row-drag handle is a `span role=button` with deprecated `aria-grabbed` and no keyboard reorder (`:398-404`).
- **`GlassCommandPalette`** renders `role="listbox"` results but has no `aria-activedescendant`, no option ids and no combobox role on the input (`src/components/interactive/GlassCommandPalette.tsx:614-620,677-678`). Screen readers hear nothing as the user arrows through results.

## What is outdated

- `@media (prefers-contrast: high)` is used in 16 places (for example `src/styles/glass.css:4055`, `src/components/accessibility/GlassFocusIndicators.css:56`, `src/utils/a11y.ts:301,973`, `src/hooks/useAccessibilitySettings.ts:173`, `src/components/accessibility/AccessibilityProvider.tsx:105`). The Media Queries Level 5 values are `more | less | custom | no-preference`, and evergreen browsers do not match `high`. There are zero `prefers-contrast: more` queries.
- `aria-grabbed` (`GlassDataGrid.tsx:404`) is deprecated in ARIA 1.1.
- The luminance threshold `0.03928` (`contrastGuard.ts:522`) is the old sRGB constant. It is harmless, but it shows the WCAG 2 math was copied rather than owned. Nothing in the codebase prepares for APCA / WCAG 3, which matters most for translucent surfaces.
- The colour parser accepts only the legacy comma `rgb(r, g, b[, a])` syntax (`contrastGuard.ts:531-546`, `:554-567`). It ignores `hsl()`, `oklch()`, hex, the modern space syntax, `color-mix()` and CSS variables. Unknown colours silently become white.
- The Nov 2025 reports (`reports/a11y_summary.md`, `FOCUS_MANAGEMENT_SUMMARY.md`, `focus-management-report.json`) reference `/home/user/auraglass/...` paths and quote APIs that do not exist. `src/lib/contrastGuard.ts` with `minRatio` / `enableSampling` props (`reports/a11y_summary.md`, "ContrastGuard Component (exists but unused)") is not in the repo. Archive them.

## Duplication

- **Contrast math exists in at least 5 places:** `utils/contrastGuard.ts` (class), `utils/contrast.ts:77-89`, `theme/color.ts:61`, `hooks/useLiquidGlassBackdrop.ts` (`luminanceFor`), and the test's own copy in `src/__tests__/glass-contrast.spec.ts:18-37`. Each has its own parser.
- **6 focus traps and 6 announce/live-region implementations** (table above). `FocusScope` and `FocusTrap` both trap Tab, both restore focus, and both are used by overlays.
- **4 accessibility-settings sources:** `AccessibilityProvider`, `useAccessibilitySettings`, the `a11y.ts:970` watcher and `GlassA11y`'s local `useState`. None of them is read by the glass material.
- **Reduced-motion:** `hooks/useReducedMotion.ts` and `hooks/useReducedMotion.tsx` both export `useReducedMotion`, plus 3 more providers or hooks.
- **Roving focus:** `primitives/RovingFocusGroup.tsx` (255 LOC) plus a re-export alias. No component uses it. Tabs, Menubar, Menu, ContextMenu, TreeView, Accordion and Toolbar each hand-roll `querySelectorAll` plus `focus()`.

## Fake complexity

- **`ContrastGuard` sampling pipeline** (`src/utils/contrastGuard.ts`):
  - `captureBackdrop` always returns `null` (`:343-353`).
  - The canvas path in `performBackdropSample` is unreachable, because `sampleLiquidGlassBackdrop` never returns `source: "fallback"` for a non-null element (`src/hooks/useLiquidGlassBackdrop.ts:121-123,168`).
  - "Opacity improves contrast by 30%" is a made-up linear factor (`:509-510`).
  - The blur step "estimates" a 1.2× improvement (`:470`).
  - Fallback mode "assumes" it meets the requirement (`:481`).
  - The error path returns `meetsRequirement: true` (`:685`).
  - `analyzeImageData` hard-codes `contrast: 4.5` with the comment "Will be calculated properly in real implementation" (`:387`).
- **`applyContrastAdjustment` writes to nothing.** It writes `--glass-surface-opacity`, `--glass-adaptive-tint`, `--glass-adaptive-blur-multiplier` and the class `glass-contrast-fallback` (`src/utils/contrastGuard.ts:735-764`). No CSS in `src` reads any of them. Only `--liquid-glass-adaptive-tint` is consumed, and only by Dialog/Drawer. `liquid-glass-contrast-fallback` (`LiquidGlassMaterial.tsx:514`) also has no CSS.
- **`.glass-contrast-guard` is just `color: var(--glass-theme-text, var(--glass-text-primary))`** (`src/styles/glass.css:572-574`), applied 436 times as if it were a guard.
- **`GlassA11y` (1,124 LOC) is a demo panel, not a feature.**
  - Its config is "Mock accessibility configuration state" (`src/components/accessibility/GlassA11y.tsx:152-156`).
  - "Run accessibility tests" waits on a timer and returns hard-coded scores (`:236-285`), for example "WCAG 2.1 AA Compliance: passed, 95".
  - The "Reduce Transparency" toggle changes only local state, and the button has no accessible name, no `role=switch` and no `aria-checked` (`:903-915`).
  - Its Tailwind classes (`w-12 h-6 bg-gray-700 translate-x-6`) are only partly shimmed.
- **`AccessibilityProvider` toggles classes nothing styles.** It sets `.high-contrast`, `.large-text` and `data-color-blindness` on `<html>` (`src/components/accessibility/AccessibilityProvider.tsx:181-194`). No CSS selector in `src` targets them.
- **`GlassA11yAuditor` (726 LOC)** lists `"color-contrast"` as a rule (`src/components/interactive/GlassA11yAuditor.tsx:72`) but implements only `querySelectorAll` heuristics (`:137-234`). No contrast is computed, and it does not use the `@axe-core/react` dependency the package already declares.
- **`contrastguard-integration-report.json` is self-describing theatre.** Its own strategy line reads: "Added imports and TODO comments for manual integration", 76 "successful". Many of those wrappers became layout-level `<ContrastGuard as="div">` around whole stacks (`src/components/layout/HStack.tsx:54-64`). That costs per-instance observers and adds no legibility.
- **`FOCUS_MANAGEMENT_SUMMARY.md` claims "100% Coverage Achieved (284/284 components)".** The basis is one global CSS selector list, the same one that removes the indicator from `[aria-disabled="true"]` (`GlassFocusIndicators.css:113-116`).

## Recommendations for AuraGlass 5.0

1. **Delete the fake contrast layer.** Remove `ContrastGuard` (component and class), `TextWithContrast`, `HighContrastText`, `useAutoTextContrast`, `.glass-contrast-guard`, the `data-meets-wcag` indicator, `GlassA11y`, `GlassA11yAuditor` and `AccessibilityProvider`'s unstyled classes. Do not ship an "AA" badge that is computed from invented numbers.
2. **Replace it with a material legibility contract, enforced in CSS** (no per-instance JS):
   - Every glass material token gets a guaranteed scrim/fill floor for each `contrastHint` (light / dark / mixed).
   - Text on glass uses vibrancy-style roles (`--glass-on-surface-primary/secondary`) that are defined per theme *and* per scrim.
   - The `clear` variant always requires a scrim over media.
   - Keep `sampleLiquidGlassBackdrop`, run it once per surface root (not per text node), and have it set a `data-backdrop="light|dark|mixed"` attribute that CSS keys off. Validate against image backdrops in a browser.
3. **One preference layer.** A single provider and CSS layer that honours:
   - `prefers-contrast: more` (and `less`/`custom`)
   - `prefers-reduced-transparency: reduce`
   - `forced-colors: active`
