# AuraGlass 5.0 Autopsy: Hooks, Utils, Contexts, Types, Client, Icons, Lib

Scope: `src/hooks`, `src/utils`, `src/contexts`, `src/types`, `src/types.ts`, `src/client`, `src/icons`, `src/lib`, `src/constants`, `src/data`, plus the `dist/` artifacts and `package.json` exports that publish them. Everything was checked against source or the built `dist/` (built Sep 5, 2026, same day as the 4.1.0 commit, so it may lag source slightly). README and certification reports were not used as evidence.

This revision merges an earlier pass (findings 01-22, corrected where adversarial verification narrowed them) with a second independent pass (findings 23-40).

## Summary and score: 3 / 10

The foundation layer is about 33,000 lines with 5 test files. A handful of primitives are good (`utils/env.ts`, the canonical `useReducedMotion`, `createGlassIcon`, the idea behind `useLiquidGlassBackdrop`). They are buried under duplication, dead code, and "AI / consciousness / biometric" theater.

The worst problems are behavior and contract defects that a consumer hits without opting in:

- Importing the root package installs global click and scroll tracking, a 1s interval that never stops, and gesture listeners for an audio engine whose sound defaults to on.
- Every per-category icon entrypoint ships all 160 icons.
- Several public subpaths (`./data`, `./forms`, `./navigation`, ...) resolve at runtime to the 5.7 MB root bundle.
- The root exports hand-written `Glass*Props` types that contradict the real component props.
- Motion preference has at least 4 hooks and 4 providers that do not compose.
- Theme state from the real `ThemeProvider` never reaches components that use `hooks/useGlassTheme` (the context it reads is never provided).
- The SSR helper component `AuraGlassClientBoundary` itself causes a hydration mismatch.

A premium first-party system has one preference source, one theme hook, one color-math module, a tree-shakeable icon set that every component actually uses, side-effect-free imports, and public types that are the real types. None of those is true today.

## What is excellent (keep)

- **`utils/env.ts`** (`src/utils/env.ts:13-79`): small and dynamic (it does not cache at module load), with `safeMatchMedia` and `runClientEffect`. It should be the only SSR guard module. Rename `useClientEffect` (`:66`), which is not a hook but takes `useEffect` as an argument.
- **Canonical `useReducedMotion`** (`src/hooks/useReducedMotion.ts:11-42`): it is hydration-safe (initial value `false`, updated in an effect) and has about 190 call sites. Keep the name and re-implement it on `useSyncExternalStore` plus a provider override.
- **`createGlassIcon`** (`src/icons/createGlassIcon.tsx:17-66`): a lucide-compatible API (`size`, `absoluteStrokeWidth`, `forwardRef`, `currentColor`) on a 24-unit grid with a 2px round stroke, and no third-party dependency. The icon entry has no `"use client"`, so icons are RSC-renderable, which is correct. This is the right base for an owned icon set.
- **`useA11yId`** is built on `React.useId` (`src/utils/a11y.ts:389-392`), and components use `useId` 177 times. Random-ID generation (`generateAriaId`, `:53-55`) has zero callers.
- **`useLiquidGlassBackdrop`** (`src/hooks/useLiquidGlassBackdrop.ts`): the right concept (a typed backdrop sample with `luminance`, `contrastHint`, `requiresDimming`, `source`), and it has a test. The implementation has real sampling bugs (finding 31), so keep the API and fix the internals.
- **`SettingsContext` API shape** (`src/contexts/SettingsContext.tsx:17-80`): a typed `Settings` object, an injectable `SettingsStorageAdapter`, a versioned storage key, and a tri-state `reducedMotion`. It is the right blueprint for the 5.0 preference root, but the implementation is buggy (finding 27) and only the never-shipped `client/pages/SettingsPage.tsx` consumes it.
- **`colorInput.ts`**: has a test and 7 internal consumers.

## What is mediocre

- **`lib/utilsComprehensive.ts`** is the de facto utility core (279 importers), but its quality is low:
  - `hexToRgba` handles only 6-digit hex (`src/lib/utilsComprehensive.ts:16-21`).
  - `debounce` and `throttle` have no cancel or flush (`:178-204`).
  - `storage` relies on try/catch instead of an SSR guard (`:301-336`).
  - `cn` runs `twMerge` on class lists that are mostly `glass-*` names, which tailwind-merge does not understand (`:11-13`).
  - `src/lib/utils.ts` exists only to re-export `cn`.
- **`useVirtualization.ts`** (696 lines, 5 public variants at `src/index.ts:886-892`): variable-height mode is an O(n) linear scan on every scroll (`src/hooks/useVirtualization.ts:130-155`), and measured sizes are stored in a React state `Map`, so every measurement re-renders. Wrap `@tanstack/virtual`, or keep a single focused implementation.
- **`icons/components.tsx`** has three problems:
  - Lucide alias names that are not distinct glyphs: `CheckCircle2`, `Code2`, `Undo2`, `Maximize2`, and `FolderKanban = Folder` (`src/icons/components.tsx:418,445,522,622,633,794,798`).
  - Semantic aliases with the wrong glyph: `command: Search` in the registry (`:830`).
  - Composite glyphs built by concatenating full-size nodes, which produces wrong drawings. `ZoomIn = [...search, ...plus]` puts a 14-unit plus centered at (12,12) over a lens centered at (11,11) with r=7, so the plus overflows the lens (`:821`, geometry at `:52-60`). `VolumeX` draws a full 12-unit X over the speaker (`:803`). `XCircle` puts an X whose corners almost touch the r=9 circle (`:819`).
- **`GlassIcon` named lookup** (`src/icons/components.tsx:846-854`): `name` is typed `keyof ... | string`, so typos compile, and unknown names render a `Circle`.
- **`useMotionPreference.ts`**: closures are rebuilt every render, and `normalizeEase` silently maps unknown easing values to `easeInOut` (`src/hooks/useMotionPreference.ts:55-94`).
- **`GlassLocalizationProvider`** (`src/lib/GlassLocalizationProvider.tsx:46-72`): a "localization" provider with no `locale` prop. It hard-codes date-fns, builds a new adapter object every render, defines its own `DateAdapter` type that duplicates `utils/dateAdapters.ts`, and has zero component consumers.
- **`SeededRandom`** ("for SSR consistency") defaults its seed to `Date.now()`, which defeats the purpose (`src/utils/random.ts:7`).

## What is outdated

- **`useState` + `useEffect` media-query subscription** in every hook and provider instead of `useSyncExternalStore`. Each of the about 190 `useReducedMotion()` call sites creates its own `MediaQueryList` listener and re-renders after hydration.
- **Legacy `addListener` fallbacks** are repeated in every motion hook (`src/hooks/useReducedMotion.ts:36-39`, `src/hooks/useEnhancedReducedMotion.ts:55-58`, `src/primitives/motion/ReducedMotionProvider.tsx:21-24`).
- **`new Function(...)` feature detection** (`src/utils/browserCompatibility.ts:197,421,424`). It is root-exported, and it throws under a CSP that does not allow `unsafe-eval`.
- **`glass-api-stable.ts` "LOCKED API v1.0.0, STABILITY GUARANTEE"** (`src/types/glass-api-stable.ts:1-9`) in a v4.1 package, with zero importers. Its `GlassElevation` (4 levels, `:101-105`) already disagrees with the real tokens (5 levels, `src/tokens/glass.ts:16-21`).
- **`utils/ssr.ts` caches `canUseDOM`, `safeWindow`, and `safeDocument` at module load** (`src/utils/ssr.ts:15-31`), which `utils/env.ts:6-8` explicitly says not to do. Both modules are root-exported.
- **Quality gating that is backwards for glass**: `canUseHighQualityGlass()` requires `devicePixelRatio >= 2 && webgl` (`src/core/mixins/glassMixins.ts:252-259`). Every 1x external monitor is downgraded, even though high-DPR displays are the more expensive case for `backdrop-filter`. `getRecommendedTier()` returns `"high"` on the server and usually `"medium"` on the client.

## Fake complexity

- **`adaptiveAI`, "machine learning-driven UI"** (`src/utils/adaptiveAI.ts`): the "neural network" uses `Math.random()` weights when the weight map is empty, which is always (`:310-313`). It infers `prefersReducedMotion` from scroll speed (`:280`). It is instantiated at import (`:563`). See finding 01.
- **`emotionalIntelligence.ts`**: a "biometric" buffer with `heartRateVariability`, `skinConductance`, and `breathingRate` defaults (`src/utils/emotionalIntelligence.ts:318-329`), instantiated at import (`:593`) and used by `EnhancedGlassButton`. Inferring emotion from user behavior is both fake and a legal and reputational liability; for example, the EU AI Act restricts emotion recognition in workplace and education contexts.
- **`aiPersonalization.ts` (571), `consciousnessOptimization.ts` (599), `types/consciousness.ts` (518, with eye-tracking FPS and biometric intervals at `:187-200`), `ConsciousnessStreamProvider`**: 28 non-test files mention "consciousness". None of it relates to rendering glass.
- **`useAccessibilitySettings` screen-reader "detection"** (`src/hooks/useAccessibilitySettings.ts:60-72`): `speechSynthesis.getVoices().length > 0` and `"webkitSpeechRecognition" in window` are true in essentially every desktop Chrome, so most sighted users are flagged `screenReader: true`. Detecting assistive technology is also a privacy anti-pattern.
- **`useGalileoStateSpring` / `useAuraStateSpring`**: plain `useState` with `isAnimating: false` hard-coded (`src/hooks/useGalileoStateSpring.ts:13-25`).
- **`analytics.track` / `analytics.page`**: guarded by `isProduction()` and then by `isDevelopment()`, so they never run (`src/utils/productionUtils.ts:410-440`).
- **`utils/createGlassStyle.ts` `variant`**: `primary`, `success`, `warning`, `danger`, and `info` produce byte-identical white gradients (`src/utils/createGlassStyle.ts:51-56`), so the option exists but changes nothing. It is also the textbook "generic lib" recipe: a white gradient, a 1px white border, and `blur() saturate(1.5)` on every surface, with `transition: all` (`:76-89`).
- **`usePerformance`** sends `HEAD /favicon.ico` to the consumer's origin to "estimate latency" (`src/hooks/usePerformance.ts:157-166`).
- **Icon category entrypoints** look tree-shakeable but are not (finding 02).
- **`src/client`**: pages and a HeroSection that the published package never contains (finding 25).
- **Dead code** with zero importers and no root export: `utils/smartColorExtraction.ts` (1,028), `utils/a11yTesting.ts` (725), `utils/a11yEnhancers.tsx` (670), `utils/performance.ts` (502), `utils/dynamicTheme.ts` (373), `utils/compatibility.ts` (309), `utils/testSetup.ts` (348, Jest setup inside `src/utils`), `utils/testing/renderWithProviders.tsx`, `hooks/useParallax.ts`, `icons/createIcon.tsx`, `types/glass-api-stable.ts` (315), and `constants/runtimeFlags.ts`. That is about 4,600 lines. `hooks/useReducedMotion.tsx` (231) cannot be reached (finding 13), and `utils/a11y.ts` `generateAriaId` has no callers.

## Recommendations for AuraGlass 5.0

1. **Make every import side-effect-free.** Delete `adaptiveAI`, `emotionalIntelligence`, `aiPersonalization`, `consciousnessOptimization`, `ConsciousnessStreamProvider`, `types/consciousness`, and `ai-client`, or move them into an opt-in `aura-glass/labs` package with explicit `init()` calls. Replace the `glassSoundDesign` singleton with a lazy `createSoundEngine()` that is off by default and enabled only through the provider. Add a CI check that imports each `dist` entry in jsdom and fails on any listener, interval, rAF, or `<html>` mutation. Then declare `"sideEffects": ["**/*.css"]` honestly.
2. **Use one preference store.** Build a `usePreference('reducedMotion' | 'reducedTransparency' | 'contrast' | 'colorScheme')` hook on `useSyncExternalStore`, with one shared `MediaQueryList` per query, `getServerSnapshot` returning `false`, and an override from a single `<AuraGlassProvider settings>`. That provider is a fixed `SettingsContext`: persist the raw tri-state, resolve "system" only when reading, keep side effects out of updaters, and use the same `isReady` on server and client. Rebuild `useReducedMotion` on top of it and keep the name. Delete `useEnhancedReducedMotion`, `useReducedMotion.tsx`, `MotionPreferenceContext`, `AnimationContext`, ThemeProvider `PreferencesContext`, the screen-reader detector, and the raw `matchMedia` calls. Set framer `MotionConfig reducedMotion` once inside the provider.
3. **Use one theme hook.** Delete `core/themeContext` and `hooks/useGlassTheme`, and point every consumer at the `ThemeProvider` hook. Add a test that renders each themed component under `ThemeProvider` in dark mode and asserts that the theme changes the output.
4. **Rebuild icons as one module per glyph** (`src/icons/glyphs/search.tsx`):
   - Add `/*#__PURE__*/` to the `createGlassIcon` calls, make categories pure re-export barrels, and set a size budget of under 1 KB for a single-icon import, enforced in CI.
   - Make icons decorative only when no `aria-label` or `title` is present; otherwise add `role="img"` and a `<title>`.
   - Redraw composite glyphs (ZoomIn, VolumeX, XCircle) on a real grid instead of concatenating nodes. Drop lucide alias names and wrong-glyph aliases, and type `GlassIcon name` strictly.
   - Migrate the 129 inline SVGs and all emoji UI icons to the set, and add a lint rule banning emoji and raw `<svg>` in `src/components`. A premium system screenshot depends on this.
5. **Public types must be the real types.**
   - Delete the `src/types.ts` shadow props and export `Glass*Props` from the components.
   - Define `GlassElevation`, `GlassVariant`, and `GlassIntensity` once, generated from the tokens.
   - Add `expect-type` tests, e.g. that `ComponentProps<typeof GlassModal>` is assignable to the exported `GlassModalProps`.
   - Resolve `@/` aliases in `.d.ts` output and fail the build if `dist/**/*.d.ts` contains `from "@/`.
6. **Make subpath exports honest.** Each subpath gets a real entry and a real type barrel, or it is removed. No subpath may alias `dist/index.mjs`. Remove `./utils/env`, `./hooks/useGlassProbes`, `./core/mixins/glassMixins`, and `./client`. Split the root into a server-safe utilities entry (`aura-glass/utils`, no directive) and per-file `"use client"` components, instead of one 5.7 MB client bundle.
7. **Collapse utilities into small modules:**
   - `color`: one parser that understands oklch and color(), and one luminance/contrast implementation, replacing 13 luminance copies and 10+ parsers.
   - `env`: keep `utils/env.ts` and delete `utils/ssr.ts`'s cached globals.
   - `dom`: shared DOM helpers.
   - `timing`: debounce and throttle with cancel and flush.
   - `ids`: `useId` only.

   Use one `createGlassStyle` that emits CSS variables only and has real variants. Remove `productionUtils` from the public surface. Replace `export *` in `src/index.ts` with a generated, reviewed export manifest, and fail CI on duplicate names.
8. **Prune hooks to those that serve the material.**
   - Keep: `useLiquidGlassBackdrop` (with sampling fixed: walk the stack to the first opaque layer, composite alpha, parse modern color syntax, throttle on both leading and trailing edges), `useAutoTextContrast`, the preference hook, `useGlassFocus`, and one virtualization hook.
   - Add: `useControllableState`, `useMediaQuery`, `useComposedRefs`, `useIsomorphicLayoutEffect`.
   - Move to `aura-glass/motion` or `labs`: physics, z-space, magnetic, tilt, sortable, and draggable hooks.
   - Delete: `useGalileoStateSpring`, the three performance hook families, the favicon latency probe, and the about 4,600 dead lines.
9. **Fix the SSR helpers first.** `AuraGlassClientBoundary` must start `false` on both server and client (or use `useSyncExternalStore` with a server snapshot of `false`). Fix the lazy initializers in `useDeviceCapabilities` and `useEnhancedReducedMotion` the same way.
10. **Move `src/client` demo pages to the docs app.** Delete `src/data`, `src/constants` (inline the flag), `glass-api-stable.ts`, and the test harness files under `src/utils`.
11. **Move server-only packages** out of `dependencies`, and make `framer-motion` a real peer or an internal dependency, not both.
12. **Test the foundation.** There are 5 test files across about 33,000 lines. For every exported hook and provider, add `renderToString` followed by `hydrateRoot` with zero mismatch warnings. Add side-effect-free import tests and a bundle-size budget per entrypoint.
