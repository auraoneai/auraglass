# AuraGlass 5.0 Autopsy: Packaging, SSR/RSC, React/Next, DX

Scope: `package.json`, `rollup.config.js`, `scripts/build-all.js`, `scripts/postbuild-client.js`, `tsconfig*.json`, `src/index.ts`, `src/{client,ssr,server,registry}`, built `dist/` (built 2026-09-05, matches the 4.1.0 commit), `INSTALLATION.md`, `README.md`, `docs/package-entrypoints.md`, `scripts/ci/{run-next-integration,run-vite-integration,verify-pack,verify-tree-shaking}.js`, `reports/3.2-release/*`, `reports/exports_types_check.md`.

How I checked it: I read the code and ran lightweight commands: `npm pack --dry-run --json --ignore-scripts`, `require`/`import` timing of `dist`, and esbuild tree-shaking probes against `dist` and `src` with metafiles. I did not run Next, Vite, Playwright, Storybook, or a full build. The recipe PNGs did not render in this environment, so this report makes no visual judgments.

---

## 1. Summary and score

**Score: 3.5 / 10** for install-to-beautiful-UI DX and packaging quality.

AuraGlass ships as one 5.5 MB, unminified, single-file bundle with `"use client"` at the top. Every consumer installs a backend stack: Express, Redis, ioredis, Socket.IO server, JWT, bcrypt, Pinecone, OpenAI, Google Vision and `@sentry/node`. None of it is reachable from any UI entry point.

Tree shaking is effectively broken. `import { GlassButton } from 'aura-glass'` costs **1.98 MB minified / 558 KB gzip**, including chart.js. The CI gate that should catch this has a budget set to 1.7 MB, so it passes anyway.

The "SSR" and "server" entry points are no-op shims left over from styled-components. Two subpath entries (`/primitives` and `/theme`) call `createContext` at module scope without `"use client"`. They will crash if imported from a React Server Component.

There are real strengths: a correct `exports` map with types-first conditions, honest docs about which subpaths are fake, a good CLI, SSR-safe motion hooks, and RSC-safe `/app-shell` and `/icons` bundles. The plumbing is fixable. The shipped artifact is not what a premium first-party design system ships.

## 3. What is excellent (keep)

- **The `exports` map shape.** It puts `types` first, uses `import`/`require` pairs and has a `./package.json` escape hatch. Focused icon subpaths (`/icons/action`, …) are tiny (`dist/icons/index.mjs` 30 KB, React-only imports). `package.json:11-231`.
- **Honest entry-point docs.** `docs/package-entrypoints.md` openly says `/forms`, `/data`, `/navigation`, `/overlays` and `/marketing` resolve to the root bundle. It also says `/workflows` is the same runtime as `/workspace`. Keep this candor, but fix the underlying problem.
- **RSC-safe chrome bundles.** `dist/app-shell/index.mjs` (10 KB) and `dist/icons/index.mjs` have no hooks or context. They can render as Server Components today. A tree-shaking probe showed `GlassAppShell` plus icons at about 50 KB. This is the right model for 5.0.
- **Focused primitive subpaths** (`/primitives/slot`, …) carry `"use client"` and tree-shake to about 600 bytes (`Slot`, measured).
- **SSR-safe motion detection.** `useReducedMotion` starts at `false` and reads `matchMedia` in an effect, which avoids hydration mismatches (`src/hooks/useReducedMotion.ts:11-30`).
- **The CLI** (`bin/aura-glass.cjs`, 1,024 lines). It offers `list`, `info`, `add <recipe>`, `audit deps/imports`, `migrate lucide|radix|mui` and `doctor`. This is genuinely good DX and a differentiator. Keep it and extend it with `init`.
- **The pack verifier concept.** `verify-pack.js` packs, extracts, checks that the `.d.ts` files named in `exports` exist, rejects nested `node_modules` or bundled React, and runs a real install-and-import smoke. The uncommitted fix (§9) makes it work on npm 11+.
- **Server dependencies are externalized correctly.** No UI entry imports express, redis, openai or similar (verified by scanning bare imports in every `dist/*/index.mjs`). The weight lives in `dependencies`, not in the bundle.

## 4. What is mediocre

- **A single flat bundle per entry.** `scripts/build-all.js:142-156` uses esbuild `bundle: true`, unminified, one file per entry. This throws away module boundaries, so `sideEffects` can no longer help consumer tree shaking. The root bundle has 353 top-level `X.displayName = "…"` assignments and 4 top-level `ChartJS.register(...)` calls (`dist/index.mjs:50398-50454`). Bundlers must keep these.
- **Fake subpaths.** `/forms`, `/data`, `/navigation`, `/overlays` and `/marketing` point their types at narrow `.d.ts` files, but `import`/`require` go to `dist/index.mjs` (`package.json:134-163`). `/workflows` runtime points at `dist/workspace/index.mjs` (`package.json:154-158`). Types and runtime disagree by design.
- **Self-contained subpath bundles duplicate code.** `/primitives`, `/app-shell`, `/workspace` and `/theme` each inline their own copies of shared modules. `dist/primitives/index.mjs:3181` creates its own `LiquidGlassLayerContext`, and the root bundle creates another. An app that mixes `aura-glass` and `aura-glass/primitives` gets two contexts, so a provider from one entry is invisible to consumers from the other.
- **`dist/esm` is a full `tsc` emit** (765 files, 7.1 MB; `scripts/build-all.js:182-184`). The `exports` map only reaches 12 of these files, and the rest are dead weight in the tarball. 228 of those files still contain unresolved `@/…` path aliases, for example `dist/esm/components/button/GlassButton.js:5` `from "@/hooks/useReducedMotion"`. They would break if anyone reached them.
- **`.d.ts` path-alias leaks** in 6 declaration files, for example `dist/components/theme/PersonaPicker.d.ts:2` `from "@/theme/designMatrix"` and `dist/contexts/ConsciousnessStreamProvider.d.ts:2`. For consumers these types resolve to `any` or fail to compile.
- **Types are not checked against the real resolution model.** `tests/types/tsconfig.json` uses `moduleResolution: "node"` with `paths` pointing into `dist`, so it never exercises `exports`. The package has no `"type"` field, so `.d.ts` files serve both ESM and CJS conditions. Under `node16`/`nodenext` that is the "masquerading as CJS" failure mode.
- **Budgets exist but are not enforced.** The `bundlesize` budgets in `package.json:528-549` all fail today: root 1,026 KB gzip vs a 950 KB limit, CSS 48.9 KB vs 35 KB, three 39.5 KB vs 35 KB. `size-check` is not wired into CI (`.github/workflows/*` has no `size-check`).
- **The build ships without type-checking.** The legacy rollup TS plugin sets `check: false` (`rollup.config.js:102`), and the esbuild path never type-checks. The declaration emit (`build-all.js:209`) is the only tsc pass that runs during `build`.
- **Recipes are inline-style soup.** `src/registry/recipes.ts` (2,089 lines) has 203 `style={{…}}` blocks, 112 hex colors, 98 `rgba(` values, **0** `var(--…)` token references and only 27 `glass-*` classNames. The "beautiful out of the box" recipes get their look from hard-coded inline CSS, not from the design system.
- **A home-grown utility-class system with holes.** Components use about 1,353 distinct `glass-*` class tokens, but `dist/styles/index.css` defines only 1,245 classes. **832 referenced `glass-*` classes have no CSS rule.** That includes 361 utility-shaped ones (`glass-z-20`, `glass-pt-4`, `glass-font-mono`, `glass-ring-4`, `glass-opacity-100`) and 98 malformed codemod leftovers (`glass-text-primary-glass-opacity-90`, `glass-max-glass-h-64`, `glass-inline-glass-flex`, `glass-border-white/15`). These are silent styling no-ops.

## 5. What is outdated

- **styled-components era leftovers.** `aura-glass/ssr`, `aura-glass/server` and `aura-glass/registry` export `AuraGlassSSRProvider`, `collectStyles`, `createStyleSheet`, `StyledComponentsRegistry`, `ensureStyledComponentsRegistry` and similar. All are no-ops (`src/ssr/StyleSheetManager.tsx:1-8,28-46`, `src/server/registryGuard.ts:1-18`, `src/registry/StyledComponentsRegistry.tsx:5-15`). The README still tells users to "use the SSR provider when your app needs AuraGlass hydration helpers" (`README.md:354-357`). The Next smoke still installs `styled-components@6.1.19` and wraps the layout in the dead registry (`scripts/ci/run-next-integration.js:66,164-166`).
- **React 18-pinned toolchain while claiming React 19.** Dev deps pin `react`/`react-dom` 18.2.0 and `@types/react` ^18 (`package.json:449-450,471-472`). Overrides pin `"scheduler": "^0.23.0"`, the React 18 scheduler (`package.json:522`). Other dev deps are also behind: `eslint` ^8 (EOL), `eslint-plugin-react-hooks` ^4 (no React 19 / Compiler rules), `rollup` ^3, `@storybook/test` 9.0.0-alpha.2 next to 9.1.20, and the deprecated `@storybook/jest` / `@storybook/testing-library`.
- **React 19 API debt.** `forwardRef` appears 705 times across 282 files (deprecated path in 19, where ref is a prop). `React.FC` appears 329 times across 142 files. 85 no-argument `useRef<T>()` calls are type errors under `@types/react` 19. `MutableRefObject` is used in 31 files. Global `JSX.IntrinsicElements` appears in 3 shipped `.d.ts` files (`dist/components/layout/Box.d.ts:6`, `dist/types/components/layout.d.ts:3`, `dist/components/advanced/GlassEngine.d.ts:60`), and @types/react 19 removed that global namespace. The library has no use of `useActionState`, `useOptimistic`, `use()` or `useSyncExternalStore`.
- **`Slot` reads `element.ref`.** `src/primitives/Slot.tsx:76` reads `(child as …).ref`, which logs a warning in React 19 (ref moved to `props.ref`). `composeRefs` also builds a new callback ref on every render (`Slot.tsx:8-25,80`), so the ref detaches and re-attaches each render.
- **`"prepare": "husky install"`** (`package.json:268`) is the deprecated husky v4–v8 form; husky 9 uses `husky`.
- **`reports/exports_types_check.md`** (last touched 2025-11-07) describes `exports: null`, `module: dist/index.esm.js` and "declaration not enabled". All three are false today.
- **`sideEffects: ["*.css", "src/styles/**/*"]`** (`package.json:562-565`) references `src/`, which is not published. The glob is meaningless in the tarball.

## 6. Duplication

- **Two build pipelines.** `npm run build` uses esbuild (`scripts/build-all.js`). `npm run dev` uses `rollup -c --watch` with a different config (`rollup.config.js`, which has its own external list and babel plus postcss), and that config has no `/icons`, `/primitives`, `/app-shell`, `/workspace`, `/theme` or tokens entries. Dev output does not match published output. Two near-identical hand-maintained external lists exist (`rollup.config.js:10-40`, `build-all.js:43-74`).
- **Peer and hard dependency both.** `@google-cloud/vision`, `openai`, `redis`, `framer-motion`, `react-chartjs-2` and `react-hook-form` are listed as optional peers and as dependencies (`package.json:369-414` vs `486-511`). The hard dependency wins, so "optional" means nothing. `framer-motion` ^11 as a dependency while React 19 users install 12 (the project's own React 19 smoke uses 12.38, `run-next-integration.js` React 19 deps) can nest a second framer-motion copy. Two copies means split `MotionConfig` contexts.
- **Surface components.** The root exports 18 base-surface components: `Glass`, `GlassPrimitive`, `GlassAdvanced`, `GlassOptimized`, `OptimizedGlass`, `OptimizedGlassAdvanced`, `OptimizedGlassCore`, `OptimizedGlassContainer`, `LiquidGlassMaterial`, `FrostedGlass`, `DimensionalGlass`, `HeatGlass`, `WidgetGlass`, `PageGlassContainer`, `GlassPanel`, `GlassContainer`, `GlassCard`, `GlassCardLink`. There are 3 button bases: `Button`, `GlassButton`, `EnhancedGlassButton`.
- **Theme providers.** The root `ThemeProvider` (`src/theme/ThemeProvider.tsx:1464`, a 1,606-line file that also aliases `GlassThemeProvider` at `:1606` without exporting it from root) is a different component from `aura-glass/theme`'s `GlassThemeProvider` (`src/theme/GlassThemeProvider.tsx:47`). There is also `AIGlassThemeProvider`. The Next smoke uses the root `ThemeProvider` (`run-next-integration.js` providers.tsx) and the Vite smoke uses `/theme`'s `GlassThemeProvider` (`run-vite-integration.js:151,157`). Only 7 non-theme files consume `useGlassTheme`, and 3 consume the root `useTheme` family.
- **Reduced-motion logic** appears in 38 files. Same-basename twins `src/hooks/useReducedMotion.ts` and `src/hooks/useReducedMotion.tsx` have different export sets. tsc resolves `.ts` first and esbuild resolves `.tsx` first, so type-check and runtime see different modules. Related hooks: `useEnhancedReducedMotion`, `useMotionPreference`, `MotionPreferenceContext`, `ReducedMotionProvider`.
- **`cn` is defined twice** (`src/design-system/utilsCore.ts:4`, `src/lib/utilsComprehensive.ts:11`). SSR guards are split between `utils/env.ts` and `utils/ssr.ts`.
- **CJS and ESM full copies** of every entry, and full copies across subpaths. Mixing them gives dual-package hazards for every context (see §4).

## 7. Fake complexity

- **`aura-glass/ssr` and `aura-glass/server`** are full entry points (rollup and esbuild configs, `.d.ts`, docs, tests) for 9 no-op functions (§5).
- **`aura-glass/client`.** `src/client/index.ts` declares pages (`PersonasPage`, `PlaygroundPage`, …) and `HeroSection`. `scripts/postbuild-client.js:19-33` then overwrites `dist/client/index.*` with a stub that re-exports root. The source file is a lie, and the shipped `.d.ts` for `client/pages/*` describes code that is not shipped.
- **The tree-shaking gate passes by budget.** `scripts/ci/verify-tree-shaking.js:59-63` sets `"GlassButton only"` to `maxBytes: 1700000`. `reports/3.2-release/bundle-analysis.md` records 1,616,016 bytes for one button as "Pass".
- **The "consciousness" stack in a button.** `GlassButton` imports `GlassAchievementSystem`, `GlassBiometricAdaptation`, `GlassEyeTracking`, `GlassSpatialAudio` and `GlassPredictiveEngine` (`src/components/button/GlassButton.tsx:20-32`). Even from source with perfect module boundaries, one button costs 87 KB minified, about 20 KB of it from those "advanced" modules (esbuild metafile). It also calls those hooks conditionally on props (`GlassButton.tsx:287-295`), which violates the Rules of Hooks. Toggling `predictive`, `adaptive` or `eyeTracking` at runtime throws "Rendered more/fewer hooks". Each hook throws if its provider is missing (e.g. `GlassBiometricAdaptation.tsx:823-830`).
- **Report artifacts in the public API.** `src/index.ts:764-785` exports `component_inventory_json`, `GILDED_TOKENS_CATALOGUE_MD`, `REDUCED_MOTION_100_COMPLETE_MD`, `TYPESCRIPT_FIX_PROGRESS_MD_PATH` and others. `dist/esm/scripts/build-production.js` and `dist/esm/reports/*` ship in the tarball.
- **Server services in a UI package.** `src/index.ts:918-924` admits that the AI, auth and collaboration services "are meant to be used in a Node.js backend". They still ship through `exports` (`package.json:180-204`) and drive 13 backend `dependencies`. `@pinecone-database/pinecone` is used only by `src/services/ai/semantic-search-service.ts:45`, which is not exported at all.
- **`AuraGlassClientBoundary`** is exported as an SSR helper and is itself a hydration bug (§8, finding 07).

## 9. Uncommitted CI modifications (git diff)

All three scripts get the same fix. npm 11+ changed `npm pack --json` output from a top-level array (`[ { filename, files, … } ]`) to an object keyed by package name (`{ "aura-glass": { … } }`). The old `JSON.parse(out)[0]` returned `undefined` under npm 12.2.0 (installed here), so the scripts threw "Failed to generate npm pack tarball" / "Unexpected npm pack output."

- `scripts/ci/run-next-integration.js:48-50` and `scripts/ci/run-vite-integration.js:46-48`: `Array.isArray(parsed) ? parsed[0] : Object.values(parsed)[0]`.
- `scripts/ci/verify-pack.js:137-147`: also widens the JSON-start search from `[` to `[[{]` (stdout can have log noise before the JSON). It accepts three shapes: array, a bare object with `files`, or keyed object.
- `reports/3.2-release/vite-integration.json` is the regenerated artifact from a 2026-09-05 run of the fixed script. Version is now 4.1.0 instead of 3.5.0, and the shasum and temp dir are new.

Assessment: the fix is correct and should be committed. Caveats:

1. The Next and Vite scripts call `npm pack` without `--ignore-scripts` and without the noise-tolerant JSON slice that `verify-pack.js` uses. `prepare` (`husky install`) output on stdout can still break `JSON.parse`.
2. `[[{]` can match a `[` or `{` inside preceding log lines (e.g. `[husky]`).
3. The fix shows that `prepublishOnly` (`package.json:329`) has been unrunnable on npm ≥11 since the 4.x line began. Gates documented as passing could not have run on that toolchain.

## 10. Recommendations for AuraGlass 5.0

1. **Split the packages.** Publish `aura-glass` as UI only, with dependencies `clsx` and `tailwind-merge` (or neither) and peers `react` and `react-dom`. Move `src/services/**` and `server/` into a separate `@auraone/glass-server` package, or delete them. Make chart.js, react-hook-form, date-fns, framer-motion and three true optional peers. Load them only from dedicated subpaths: `aura-glass/charts`, `aura-glass/forms`, `aura-glass/motion`, `aura-glass/three`. Target: `npm i aura-glass` adds fewer than 5 packages.
2. **Ship preserved modules, not a flat bundle.** Use `tsup`/`rollup` with `preserveModules` (or plain `tsc` plus a path-alias rewrite), minified, ESM-first, with `"type": "module"`. Emit `.d.ts` and `.d.cts` per condition, and set `"sideEffects": ["**/*.css"]`. Add `/* @__PURE__ */` annotations or move `displayName` into `Object.assign` expressions. Move `ChartJS.register` into the chart component. Gate with `@arethetypeswrong/cli`, `publint`, and a tree-shaking budget of **≤ 25 KB gzip for one `GlassButton`**. Fail CI on overage.
3. **Make RSC a first-class design input.** Keep `"use client"` per file in the preserved output. Make layout and presentational components (Card, Panel, Badge, StatusDot, Text, AppShell, icons, layout) server-safe with no directive, and keep interactive ones client-only. Delete the root-level `"use client"`. Add a Next App Router fixture that imports from **Server Components**, runs `next build && next start`, and uses `@types/react@19`.
4. **Real subpaths or none.** Every subpath in `exports` must have its own runtime. Delete `/ssr`, `/server`, `/registry`'s `StyledComponentsRegistry` and the `/client` stub (keep a one-release deprecation shim that logs). Remove report and constant exports from root.
5. **Use React 19-native APIs.** Use ref-as-prop and drop `forwardRef` (React 19 as minimum, or a `ref` prop with a compat layer for 18). Fix `Slot` to read `props.ref` with stable `useComposedRefs`. Fix `AuraGlassClientBoundary` (use `useSyncExternalStore` or a mounted flag that starts at `false`). Remove the conditional hooks in `GlassButton`: strip the "consciousness" features out of base components into opt-in wrappers. Upgrade dev deps to React 19, `@types/react` 19, eslint 9 and `react-hooks` 5+ (Compiler rules), and drop the `scheduler` override.
6. **One build, one theme provider, one surface.** Delete `rollup.config.js` or make it the build. Merge the root `ThemeProvider` and `/theme` `GlassThemeProvider` into a single CSS-variable provider. Collapse the 18 surface components to one `GlassSurface` primitive with `material`/`elevation` props, and keep one button.
7. **Fix the class system or replace it.** Generate `glass-*` utilities from tokens with a lint that fails on any className the CSS does not define (832 today). Alternatively, adopt CSS Modules or vanilla-extract with typed variants and drop string utilities.
8. **Recipes must use the system.** Rewrite recipes to use only components, tokens and CSS variables, with zero inline hex. Add `aura-glass init` to the CLI: detect Next/Vite, add `import 'aura-glass/styles'` to the root layout, add a backdrop/canvas component (glass over flat white looks flat), and scaffold one recipe. Measure "time to first beautiful screen" in the Next fixture with a `next build`.
9. **Trim the tarball.** Exclude sourcemaps, or publish them separately. Exclude `dist/esm` leftovers, reports and scripts. Target < 2 MB packed.
10. **Commit the npm 11 pack-output fix.** Also add `--ignore-scripts` and noise-tolerant parsing to the Next and Vite scripts, and re-run `prepublishOnly` end-to-end remotely in CI before trusting any prior "pass" ledger.
