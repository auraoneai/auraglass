## Decision

Option **(b)**: `auraglass/no-inline-glass` stays at `error` for all files
except 54 files listed in `eslint/no-inline-glass-baseline.json` (sorted file
list generated from `eslint src --format json`). Baseline entries demote the
rule to `warn`; violations in any unlisted file still fail `lint:check`.

Option (a) — fixing all 142 sites — was rejected for the 4.1.1 patch window:
each site is a hand-tuned glass material constant; rewriting them to
`createGlassStyle()` calls (the rule's autofix) was observed to generate
wrong-scope imports and invalid option shapes, i.e. it changes rendered
output. A mechanical mass-rewrite is not safe to ship blind in a trust patch.

## Ratchet (shrink-only)

`tests/eslint/no-inline-glass-baseline.test.ts` fails when:

- an entry is added for a file that does not currently violate
  (`eslint --rule '{"auraglass/no-inline-glass":"error"}'` per listed file must
  report ≥1 violation),
- a listed file stops violating (it must leave the baseline),
- the list grows vs. `HEAD` (`git show` subset check), or
- the list is unsorted/duplicated.

`tests/ci/no-gate-bypass.test.ts` (PLAT-068) additionally fails on
`|| true`, `--no-verify`, `allow_failure: true` on the release gates, a
mutating `lint` script, or a missing/unsorted baseline.

## Burn-down

54 files / 142 violations remain. The burn-down owner converts each file's
inline glass objects to `createGlassStyle()` calls manually (token-verified),
deleting the baseline entry in the same PR; the ratchet enforces monotone
shrinkage. No `--no-verify`, no `|| true`, no dropping `lint:check`.
